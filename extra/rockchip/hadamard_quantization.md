# Fixed-sign block-Hadamard INT8 quantization

`ONPU_INT8_HADAMARD=128` enables an experimental CPU transform for projection input depths 2048, 3072 and 4096. The default is zero. The exact TeleChat2 F16 checkpoint/context-512 app recipe enables it; this is not an all-model or maximum-context qualification.

Each 128-channel block uses the same fixed sign vector for activations and weights, followed by a Walsh-Hadamard transform. Static weights are divided by 128 after the transform; activations are not normalized. For an unnormalized Hadamard matrix `H` and sign diagonal `D`, `(x D H) (W D H / 128)^T = x W^T` in real arithmetic. FP32 rounding and quantization change outputs, so the implementation requires independent quality checks rather than an exact-original-logit claim.

The signs reproduce PCG64 seed `1281536 + projection_depth`. Packed sign bits avoid a NumPy dependency in the inference runtime. Signs are fixed before the held-out quality screen and are not selected against its targets. The approach is motivated by [QuaRot](https://arxiv.org/html/2404.00456v2), but this implementation only changes individual INT8 projection inputs and weights; it does not implement that paper's complete network/KV transformation.

`RockchipInt8Linear.prepare` selects the normalized weight role. Both parts of an existing split projection prepare independently, using their own depth's signs. The ordinary activation quantizer transforms inputs before computing the row maximum and signed INT8 codes. The fused FFN producer first computes activation and optional channel division, then transforms each existing K4096/K2048 down-input partition, recomputes finite/max checks and writes its original payload layout. NPU command registers, matrix shapes, packing and FP32 output dequantization are unchanged.

The transformed quantizer caches its unpooled program, then applies the current shared-worker scope. This prevents an earlier unpooled invocation from hiding later pool selection. FFN program keys include the block choice explicitly. Calibrated down-input fusion is enabled only with this flag; default routing remains unchanged. SDK blocked-layout quantization and norm/quant fusion are rejected for a supported rotated depth until separately qualified.

CPU checks compare complete payload/scale bytes against an independent NumPy transform and the ordinary quantizer, including zeros, signed zero, nonfinite values, overflow and active-row tails. Separate tests exercise actual base/split weight preparation and transitions between ordinary and shared workers. The production decode/prefill quantizers and FFN kernels compile to the measured prototype's ELF bytes after normalizing only the CPU dispatcher address. GNU disassembly confirms NEON arithmetic. The optional `llvm-objdump` command was unavailable; no installation or driver change was needed.

The initial linked-component experiment estimated an added 28.93 ms per TeleChat prefill and 0.90 ms per decode step, below its declared 100 ms / 2 ms screen budgets. Those estimates are not complete-request measurements. The first model cohort measures 262.54 prefill-proxy / 10.438 decode tok/s for 128 uncached inputs and 64 outputs at context 512. Its unchanged 1024-target original-reference screen passes: mean delta NLL 0.002922, case-bootstrap upper 0.012010 and worst-case delta 0.042436, below limits 0.02 / 0.04 / 0.20. Independent broad quality, maximum context and ordinary API qualification are separate gates.

## Production API qualification, November 3, 2026

Two fresh ordinary TeleChat workers measure 238.50 prefill-proxy / 10.45 decode tok/s across 20 requests, all leading both published rates, with 38 serving checks. Streaming, cancellation/recovery, cached-versus-uncached one-token output and the 448+64 boundary pass. The app profile is exact-checkpoint/context512 only; its calibration asset is hash-bound and expands 97 groups to 169 projections. Admission budgets 5 GiB plus a separate 2 GiB reserve.

This is a limited-screen-passing published-reference result, not broad/model-maximum quality certification. The first cached-prefix request compiles a new shape and takes about 1.90–1.91 seconds; those latencies are retained separately from the warmed uncached benchmark. Original services/settings/selection and fresh replies are restored. See `/home/orangepi/oNPU/docs/benchmark-telechat-hadamard-20261103.json` for both measured epochs and all limits.
