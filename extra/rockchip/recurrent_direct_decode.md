# Direct-row GDN decode

The opt-in `ONPU_GDN_DIRECT_DECODE` path avoids transposing the full recurrent state into temporary column-major storage for one decode row. It transposes 4×4 state tiles with SIMD shuffles, accumulates keys in their original order, then updates the same state rows. This keeps the existing FP32 reduction and rounding order.

The fast path requires `rows=capacity=1`, `start>0`, scalar alpha, no history, and key/value dimensions divisible by four. It also requires the complete state and output ranges to be disjoint from one another and from q, k, v, beta, and alpha. Any failed condition uses the snapshot-based general path. The option is captured in the compiled-kernel cache key.

The Qwen3.5-4B recipe enables the path only for the pinned checkpoint at context 512. The current backend preserves all 32×248,320 logit values and improves paired median decode from 6.235 to 6.424 tok/s across twelve alternating requests. The actual API passes 18 serving checks over ten measured requests, with median 78.45 prefill-proxy and 6.432 decode tok/s; 10/10 prefill and 9/10 decode requests exceed the published targets. Original sessions are restored with two fresh replies. Independent quality and model-maximum context remain unqualified; the CPU microbenchmark is not a full-model performance result. The pre-final-guard private CPU screen measured 0.387674 ms versus 0.154605 ms. Those timings do not establish a serving win.

Verification currently includes 35 CPU tests and three actual captured-rewrite fixtures.
